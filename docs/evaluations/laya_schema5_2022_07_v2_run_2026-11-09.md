## Findings

1. **A masking gap: a company's own name word survives next to its alias in news headlines.**
   - On 07-05, two DB51 headlines rendered as "… DB51 <name word>" after masking. The masker replaced the first part of
     the short form, but not its second word.
   - The guard (tightened in `fd4b409`, 2026-10-07) correctly blocked the prompt.
   - **The same residue was sent to Hermes in the v1 Laya arm** (`af2dfdde…`, Day 5 prompt), which ran before the
     guard was tightened. So v1's July 5 decision saw a partial identity cue.
   - This is a masker defect, not a Hermes error.
   - Smallest fix: add the missing name variant for that company (or the generic "first word removed" form) to the
     masking variants, then re-check the July 2022 headlines for every pool member before any rerun.
2. **A halted cycle leaves the journal and the portfolio disagreeing.**
   - `run_day` journals the 07-05 fill before the prompt is built. The halt discards that cycle's state, and
     episode-end resolution then "rejects" the still-pending order.
   - `resolve_trade_rejection` touches only `pending` rows, so the row stays `filled`. The trace's
     `rejected; journal row written` is therefore false.
   - This is a controller and tracing defect, made visible by the halt.
   - Smallest fix: when the cycle halts, treat an order already journaled as filled as filled, or report the conflict;
     and have the episode-end span report the journal's actual status instead of assuming the write took effect.
3. **The trace error text exports the cue it blocked.**
   - The `backtest_day` 07-05 status message contains the guard's text, which names the alias and a company-name
     word. That is a partial identity exposure in Langfuse.
   - Smallest fix: export only the exception type (or a redacted message) for `IdentityCueDetected`.
   - Trace `ecf2027cc1bec573a71d7c1a4a14c73e` joins the hosted traces that need your deletion authorization (left
     untouched).
